# Noctopage — build plan and module contract

PS Vita manga + e-book reader. C, VitaSDK (in WSL), libvita2d, MuPDF (AGPL-3.0).
Title ID `NOCT00001`. Unsafe VPK (no `-s` on vita-make-fself). Extended memory
(`-d ATTRIBUTE2=12`). Screen 960×544.

Vault (design + research): `C:/Users/steve/Documents/code-vault/wiki/vita-reader/`
and `C:/Users/steve/Documents/code-vault/raw/vita-reader/` (4 research reports).

## Rules for everyone working in this tree

- C (gnu11), `-Wall -Wextra -Werror`. Files ≤ 400 lines; split before that.
- **Pure modules** (no `psp2/`, `vita2d.h`, or `mupdf` includes) live where marked
  "pure" below and are built and tested on the host by `tests/Makefile` (gcc, WSL).
  Vita-only code stays thin and calls into pure code.
- NOBORU (GPL-3.0) is a design reference only. Copy no code, no assets.
- Never modify `~/vitasdk`. Third-party code lives in `third_party/`.
- Workers decode to CPU pixel buffers; **only the main thread creates or frees
  vita2d textures**.
- No libc `printf` debugging on device: use `log_printf` (core/log), which writes
  `ux0:data/noctopage/log.txt`.

## Build

- `tools/wsl.sh <script>` style: builds run in WSL as
  `MSYS_NO_PATHCONV=1 wsl -e bash <script-file>` (never `bash -lc`, it eats exit codes).
- `make` → `build/Noctopage.vpk`. `make -C tests` → host test runner, exit non-zero on failure.
- MuPDF: `tools/build_mupdf.sh` fetches the pinned 1.26.10 source tarball (sha256
  checked) into `third_party/mupdf/src/` and builds `third_party/mupdf/vita/lib/`
  (`libmupdf.a`, `libmupdf-third.a`) and `third_party/mupdf/host/lib/` for host tests.
  It must not duplicate symbols with SDK libs the app links (freetype, harfbuzz, zlib,
  libjpeg): use the SDK's copies for those.

|---|---|

| Database | `ux0:data/noctopage/library.db` (SQLite amalgamation, vendored) |
| Thumbnails | `ux0:data/noctopage/thumbs/<bookid>.bin` (raw RGBA 180×270 + header) |

| Downloads | `ux0:books/` (created if missing; also scanned) |
| Log | `ux0:data/noctopage/log.txt` |

**Book id:** 64-bit FNV-1a over (file size as 8 bytes LE ‖ first 64 KiB ‖ last 64 KiB).
Progress follows the book across moves/renames.

## Storage scan

Scan only `ux0:books/` and its subfolders, depth ≤ 8, on a worker thread (user
requested 2026-10-06). Do not scan device roots, other storage mounts, or app data.
A folder containing ≥ 2 image files and no subfolders with images is a "folder
comic". Results go into the DB; rescans are incremental by (path, size, mtime).
After a successful scan, previously indexed items outside this folder are marked
missing and disappear from My Books; progress, settings and bookmarks are kept.

## Formats

| Kind | Extensions | Engine |
|---|---|---|
| Comic archives | cbz zip cbr rar cb7 7z cbt tar | `comic/` via libarchive |
| Folder of images | jpg jpeg png gif bmp webp (+ tif tiff via MuPDF) | `comic/` |
| Reflow books | epub mobi fb2 txt html htm xhtml | MuPDF (`doc/`) |
| Fixed layout | pdf xps oxps svg | MuPDF (`doc/`) |

Image decode: JPEG via turbojpeg with scaled decode, PNG via libpng, WebP via libwebp
(scaled), GIF/BMP/TIFF via MuPDF `fz_load_image`. Pages wider/taller than 4096 px are
tiled (`img/tiles`).

## Performance pass (2026-10-06)

- Cover generation and thumbnail disk writes run on the worker. Disk hits are not rewritten. Generated caches use temporary files and refresh-aware publication.
- Background cover generation/uploads pause while reading. Selected shelf covers move ahead of other queued work.
- HTTP workers retain separate curl connection/DNS/TLS caches; request callbacks and credentials reset between transfers. Transfers use a 64 KiB receive buffer and file downloads use a 128 KiB stdio buffer. TLS verification and resumable downloads remain enabled.
- Online cover selection requests Open Library's medium image for the stored shelf thumbnail.
- Readable page copies precede sharper zoom copies; forward neighbours precede backward prefetch. Obsolete renders are discarded after a seek.
- Small libraries allocate in blocks of 128 rather than reserving all 10,000 slots. Folder names and volume order are cached per reload. Case-equivalent folder names stay distinct.
- Shelf cards use solid title panels instead of per-cover gradient strips. Tightly packed texture uploads use one memcpy.
- Failed position writes remain eligible for retry in both readers. Long menu titles are ellipsised.

This pass is source-reviewed and VitaSDK-built only: the user requested no testing. No emulator/hardware tests or timing benchmarks were run; runtime correctness and speed gains are unmeasured.

## Open-speed + controls pass (2026-10-06)

- Comic open no longer decompresses the whole archive to list names: `comic/archive.c`
  reads the ZIP central directory directly (covers, which open the same archives,
  get faster too). Non-ZIP formats fall back to the libarchive walk. Host tests:
  `archive` 927 checks, `coverimg` 41, `loader` 222, full suite 44243 — all pass.
- Reader menu gains one-tap `Landscape: On/Off` (90-degree turn, uniform scale so the
  page is never stretched; spreads stay off while turned, same as Rotate).
- Page turns come from L/R only now; d-pad and sticks pan in every mode (mirrored in RTL).
- Every thread (main + scan, covers, loader, bookld, fetch, download, backup,
  wifi-import) calls `core/affinity_use_all_cores()`, best-effort mask 0xF so CPU3 is
  used when unlocked, 0x7 fallback on stock. Cover queue 32->64 pending, 6->12 done,
  main loop drains 6/frame so art appears sooner.
- Unverified on hardware: VitaSDK build, on-device open timing, CPU3 mask behaviour,
  and the new menu/controls on a real Vita still need a playtest.

## Bugfix + performance pass (2026-10-06, later)

- `covers.c`: worker waits for DONE-queue room before decoding (no more 194 KB held
  while paused); transient cover failures retry 3x before going terminal; over-long
  paths rejected instead of truncated; forget/reset restart the retry count.

  64-bit size hint and doubling against `ARC_MAX_ENTRY`; ZIP entries read straight

  textures retire 2 frames instead of stalling; book switch still frees at once.

  from `main.c`.
- `mybooks.c`: mid-scan reload with unchanged row count rebuilds rows only (no table
